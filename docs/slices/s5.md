## What it adds

- `ground_truth/site.py`: three static pages with rahil-design's `document()`. *Answer*: headline, exhibit, key numbers, every waterfall step, the reconciliation table and the pinned run. *Rules*: the scheme table, then W0–W5 with the rule sentence (thresholds read from `out/waterfall.json`), its steps and dust, the sensitivity row and 5 example hashes linked to Basescan. *Method and data*: the pre-registered falsifiers, data sources, rerun command, file hashes and known limits. With no complete run, only the empty answer page is written and stale pages are removed.
- `ground_truth/figure.py`: the exhibit, built from the run. It finds the largest payer-payee pair among W4's removals and shows it against what the rules keep and what the other rules remove, as shares of W1's dollars. It refuses to draw when that pair is under half the dollars, since the finding would not hold.
- `scripts/check_site.py` and `scripts/screens.py`; `tests/test_site.py` (fixture run: totals, an address on a page failing the check, the empty state).

## The exhibit

"Four payments carried 85% of the week's dollars": hero 85%, rows One pair $329,000 (85%), Kept $44,690 (12%), Other rules $12,456 (3%). `pd research lint`: ok. `pd research render --sizes landscape`: 2 cards, 0 layout problems. Square and portrait fail the layout check (the figure overlaps the footer) and are not used.

PRD section 11 named a waterfall bar chain. rahil-design 4.0 has no waterfall form, and the run's finding is one pair, so the figure is a ranked-parts exhibit (`hbars`); every waterfall step stays in the table under it. Recorded in the PRD change log.
