## What slice 1 found that changes later slices

1. **x402scan's filter counts routed payments twice.** All 444 fluxa payments ($0.001 each) go payer → router `0x9c955c40…` → payee inside one facilitator transaction. Both hops are USDC transfers in a facilitator-sent transaction, so W0 counts each payment twice. W1 keeps only the hop whose sender is the authorizer. S2 must report this as its own W1 sub-row ("second hop of a routed payment"). It was $0.44 this hour; its size over 7 days is unknown.
2. **Four payments make up 25% of the hour's W1 dollars.** Meridian settled 4 payments of $26.24 to $31.89. Each went payer → contract `0x8e7769d4…` → next wallet, with 99% forwarded and a token sent back to the payer. The 4 payments move between 3 wallets in a ring (A→B, B→A, A→C, C→A). This is a W3 candidate seen in one hour only. It is not yet a finding, and no wallet is named here.
3. **Batch settlement produced 29 proxy logs and 0 payments.** The rule "skip transfers that touch a proxy" drops batch settlement entirely. S2 must decode batch-settlement transfers (deposit into the contract, then claim out of it) before W1 can count them.
4. **Coverage gap still open.** Facilitator transactions without an x402 marker are not visible on the log path. S2's full-block hour scan and nonce bounds measure them (AC-5).
5. **One hour is not a rate.** This hour's 7,459 W0 transfers are above x402scan's 7-day average of about 4,283 per hour, but its $580 is below the average of about $2,305 per hour. Nothing here should be scaled to 7 days.
